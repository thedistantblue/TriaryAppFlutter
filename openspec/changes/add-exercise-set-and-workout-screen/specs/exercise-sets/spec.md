# Spec Delta

## Purpose

Набор упражнений — самостоятельная сущность (имя + упорядоченный список упражнений с подходами и повторами), которую можно привязать к силовой тренировке и переиспользовать в нескольких тренировках.

## ADDED Requirements

### Requirement: Набор упражнений как сущность

Система SHALL хранить набор упражнений как самостоятельную сущность с идентификатором, именем и упорядоченным списком упражнений. Каждое упражнение SHALL содержать имя, количество подходов и количество повторов. Набор MAY содержать ноль упражнений.

#### Scenario: Набор с упражнениями

- **WHEN** набор содержит три упражнения
- **THEN** при чтении набора возвращаются его имя и все три упражнения в исходном порядке, у каждого — имя, подходы и повторы

#### Scenario: Пустой набор

- **WHEN** набор сохранён без упражнений
- **THEN** набор читается успешно и его список упражнений пуст

### Requirement: Связь тренировки с набором

Силовая тренировка SHALL ссылаться на выбранный набор упражнений по идентификатору. Состояние «набор не выбран» SHALL быть представимо: тренировка без набора — нормальное состояние, а не ошибка. Несколько тренировок MAY ссылаться на один и тот же набор.

#### Scenario: Тренировка создаётся без набора

- **WHEN** создаётся новая силовая тренировка
- **THEN** тренировка сохранена с пустой ссылкой на набор и не требует его наличия

#### Scenario: Тренировке назначается набор

- **WHEN** тренировке установлена ссылка на существующий набор
- **THEN** при чтении тренировки возвращается тот же идентификатор набора, а по нему — тот же набор

#### Scenario: Один набор у нескольких тренировок

- **WHEN** на один набор ссылаются две тренировки
- **THEN** обе тренировки читаются с этим набором, и набор не дублируется

#### Scenario: Ссылка на отсутствующий набор

- **WHEN** тренировка ссылается на набор, которого нет в хранилище
- **THEN** тренировка читается успешно, а набор для неё считается не выбранным

### Requirement: Сохранение наборов и связи в локальной базе

Наборы и ссылка тренировки на набор SHALL сохраняться в локальной базе и восстанавливаться после перезапуска приложения. Обновление схемы локальной базы SHALL переносить существующие данные без потерь: тренировки, созданные до обновления, SHALL остаться доступными с состоянием «набор не выбран».

#### Scenario: Перезапуск приложения

- **WHEN** приложение перезапущено после сохранения набора и привязки его к тренировке
- **THEN** набор и связь читаются из локальной базы в том же виде

#### Scenario: Обновление с прежней версии базы

- **WHEN** приложение обновляется поверх базы, где тренировки хранились без ссылки на набор
- **THEN** все существующие тренировки остаются на месте, у каждой ссылка на набор пуста, данные не теряются
