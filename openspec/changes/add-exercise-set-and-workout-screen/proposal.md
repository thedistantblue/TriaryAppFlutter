# Proposal

## Why

Дизайн экрана тренировки (борды 09–13) и кнопка входа на него с экрана деталей тренировки (борд 04) уже утверждены в Penpot, но в коде их нет: приложение не умеет показать, что за тренировка предстоит и какие упражнения в неё входят. Чтобы экран можно было собрать, в модели данных не хватает самого понятия «набор упражнений»: сейчас `PowerTraining` состоит только из имени и описания и ни с чем не связан.

## What Changes

- Новые сущности в пакете `entity`: `ExerciseSet` (набор упражнений: id, имя, список упражнений) и `Exercise` (имя, подходы, повторы).
- `PowerTraining` получает ссылку на выбранный набор (`setId`). В базе: колонка `set_id` в таблице тренировок + новая таблица наборов `exercise_set`. **BREAKING** для локальной схемы БД: schemaVersion 2 → 3, нужна миграция (`onUpgrade`).
- Новый репозиторий наборов: `BaseExerciseSetRepository` (storage_api), локальная реализация поверх Drift (storage_local_api), заглушка (storage_mock_api) — по образцу существующего `BasePowerTrainingRepository`.
- Новый экран «Тренировка» (борды 09–13) со всеми пятью состояниями: раскрытый набор, свёрнутый, набор длиннее лимита (3 строки + футер «и ещё N упражнений»), bottom sheet с полным списком, состояние «набор не выбран» с disabled-кнопками.
- Сводка под набором считается из данных набора: число упражнений, суммарное число подходов, оценка времени (4 мин на подход, округление до 10).
- Экран деталей тренировки (борд 04) получает кнопку «Начать тренировку», которая открывает экран «Тренировка» для этой тренировки.
- Тема приложения дополняется цветом `tertiary`/`onTertiary` (`#A78BFA` / `#1B1140`) — по дизайну борда 09 для кнопки «Редактировать».
- Новые строки интерфейса в `l10n` (ru/en) с ICU-плюрализацией: упражнение/упражнения/упражнений, подход/подхода/подходов.

### Non-goals

- Создание и редактирование наборов, экран выбора набора — отдельной фичей позже. В этой работе только классы и связь в базе.
- Логика самой тренировки: кнопки «Начать», «Редактировать», «Предыдущие тренировки», «Сменить набор упражнений» — заглушки (`onPressed: null` / «будет позже»), новых экранов под них не делаем.
- Демо-данные не заливаем: пока набор не создан, экран показывает только состояние борда 13.
- Большой AppBar и описание на борду 04 (в дизайне 136px, имя 28px + описание) не переносим — вне скоупа, правим только кнопку.
- Тесты не пишем: проверка — `flutter analyze` + прогон на устройстве.

## Capabilities

### New Capabilities

- `exercise-sets`: набор упражнений как сущность (имя + упражнения с подходами и повторами) и его связь с силовой тренировкой.
- `workout-screen`: экран предстоящей тренировки — пять состояний по бордам 09–13, сводка по набору, вход с экрана деталей тренировки (борд 04).

### Modified Capabilities

Нет: спецификаций у проекта ещё не было (`openspec/specs` пуст), существующие требования не меняются.

## Impact

- `packages/entity`: новые файлы `exercise_set.dart`, `exercise.dart`, правка `power_training.dart` (+ `power_training.g.dart`) и экспортов в `entity.dart`.
- `packages/storage_api`: новый `base_exercise_set_repository.dart` + экспорт.
- `packages/storage_local_api`: новая таблица и миграция в `drift/database.dart` (+ `database.g.dart`), новый `exercise_set_repository.dart`, колонка `set_id`.
- `packages/storage_mock_api`: заглушка `exercise_set_repository_mock.dart`.
- `lib/`: новый экран `workout_screen.dart` и его виджеты, правка `tabs/power/pt_details.dart` (кнопка) и `main.dart` (провайдер репозитория наборов, `tertiary` в ColorScheme, маршрут), новые строки в `l10n/app_ru.arb` и `app_en.arb`.
- Codegen: `json_serializable` и `drift_dev` — прогон `dart run melos run codegen` на машине разработчика (в песочнице Dart нет).
- Совместимость: существующие тренировки в локальной БД получают `set_id = NULL` миграцией и открывают экран в состоянии «набор не выбран».
